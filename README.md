# NAZAR-109

Аналитика обращений в единый контакт-центр 109: детектор всплесков жалоб, модель риска просрочки обращения (только Карагандинская область), прогноз нагрузки и витрина для руководителя с выгрузкой в Excel и PDF.

Полное описание — `CLAUDE.md`: развёртывание (раздел 0), готовность к внедрению (0b), план следующей стадии (0c), правила работы с персональными данными (1). Вопросы заказчику — `docs/customer_questions.md`.

## Данных в репозитории нет

Сырые выгрузки содержат персональные данные и в git не попадают — ни сами выгрузки, ни собранные из них таблицы, ни построчные результаты, ни модели. Выгрузку нужно получить у владельца данных и положить в корень репозитория (раздел 0, шаг 3). В git лежат код, агрегатные отчёты и синтетический корпус без персональных данных (`tests/fixtures/synth/`).

## Установка и запуск

Проверено на macOS, Python 3.12. На Linux и Windows вне контейнера не проверялось.

```bash
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.lock --require-hashes
uv pip install --python .venv/bin/python --no-deps -e .

.venv/bin/nazar-build-data     # сырые выгрузки -> data/unified.parquet, с проверкой разметки
.venv/bin/nazar-dashboard      # витрина: http://localhost:8501
.venv/bin/python train.py      # модель риска просрочки -> reports/ (нужна блоку риска витрины)
```

`requirements.lock` закрепляет версии всех 52 пакетов с хешами. Если после сборки контрольные числа из раздела 0 не сходятся (988 776 строк и разбивка по регионам и классам), дальше идти нельзя.

## Контейнер: написан, но не проверен

`Dockerfile` и `docker-compose.yml` написаны, но **образ ни разу не собирался**: на машине разработки нет Docker. Проверка образа запланирована на первую неделю стадии 2 (раздел 0c). Пять проверок, которые нужно пройти при первой сборке, перечислены в разделе 0b, «Контейнер — инструкция»: сборка образа, витрина с восемью блоками, Excel, PDF с графиками, сборка данных с эталонными числами. Пока они не пройдены, рабочий путь — установка выше.

## Что ещё не готово

Входа и ролей нет: витрину поднимать только во внутренней сети. Нет журнала действий и регулярного обновления данных. Проверки конвейера данных запускаются только на реальных выгрузках, поэтому CI нет. Полный список с оценкой каждого пункта — раздел 0b, план по неделям — раздел 0c.
